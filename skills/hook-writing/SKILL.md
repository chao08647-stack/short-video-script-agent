# 开场设计

## 用途与触发

当脚本需要快速交代场景、问题或主题，或人工反馈认为开场拖沓时使用。只负责开场表达。

## 输入

受众、已批准角度、目标风格、可使用的事实。

## 产出

一个简短开场镜头的旁白与字幕，并保持与后续内容一致。

## 操作约束

1. 优先用可理解的问题或场景引入，尽快交代主题。
2. 避免空泛的震惊、绝对化承诺和无依据效果数字。
3. 开场不能消耗大量时长，也不能制造与产品资料不一致的焦虑。
4. 开场修改后保留后续事实主线，并重新估算当前脚本。

## 验证示例

用户认为“今天我要给大家介绍一款非常好用的软件”拖沓，可改成“视频剪好了，字幕怎么加？”；不能改成“十秒搞定所有字幕”。
