# 需求：有依据的短视频脚本 Agent

## 用户、问题与目标

本项目对应小影校招考核第 4 题。目标用户是需要制作短视频的创作者或内容运营人员。他们提供主题、受众、平台、目标时长和风格，希望得到能继续编辑、拍摄或剪辑的文字脚本，并能确认其中的产品事实来自哪里。

生成一段流畅文案不足以完成任务：脚本可能超时、编造功能或效果数据、与品牌规则冲突，也可能缺少必要资料。Agent 必须观察真实工具返回，再决定补查、修订、追问或停止。

## 已确认范围

- 主语言 Python，运行入口 CLI，LangGraph 负责有状态的模型工具循环。
- 项目内提供 16 个业务技能包。模型按任务需要加载技能，目标是由整套评估检查技能覆盖；单次任务不强制遍历全部技能。是否实际覆盖以对应模式的 Trace 为准，设计用例不能替代已运行证据。
- 创作方向、初稿和终稿三个阶段均要求人工审核。用户批准、提交修改意见或取消，由模型执行具体修改。
- 输入资料按题面采用合成产品素材与品牌规则，支持功能介绍、操作教程和使用场景等创作形式。
- 输出文字脚本、检查结果、来源及运行记录；不要求输入真实视频，也不生成画面、配音或 MP4。
- 模型服务不可用时可以显式选择离线 Mock。Mock 仅说明工程流程能够运行，不证明真实模型的工具选择或创作效果。

## 输入与产物

创作请求由 `brief` 中的 `topic`、`audience`、`platform`、`target_seconds`、`style` 组成。请求可指定资料集、额外说明、用户已有初稿和调用上限。缺少创作字段是可处理的业务情况，不通过偷偷填入默认需求来掩盖。

资料集由带 `source_id`、版本、原文和结构化事实的材料，以及品牌禁用表达、估时参数等规则构成。数据中的小剪 App、澄音 H1 等名称和事实均为合成测试材料。平台表达建议也是项目自定义的创作模板，不代表抖音、B站或小红书的实时官方政策。

最终产物应包含：

- 标题与分镜；每镜的画面文字描述、旁白或字幕、来源 ID。
- 产品断言与支持原文的对应关系。
- 各镜头和总时长的估算，以及采用的估时假设。
- 品牌与事实检查结果、风险、资料缺口和真实任务状态。
- 方向方案、稿件版本、人工审核历史及模型／工具 Trace。

等待人工的稿件、检查未通过的稿件和达到上限的任务均不能标为完成。导出中间产物也必须保留这些状态。

## 成功标准与验收映射

下表是需要满足的验收目标，不是已通过清单。当前工程已实现对应机制，但本地模型尚未完成正常脚本的三阶段全链路，16 个技能的整体效果也未得到证明。现有真实记录中，无资料与调用上限场景通过其验收条件；其余缺口以 [评估文档](03-evaluation.md) 为准。

| 验收点 | 应观察到的行为 | 不接受的替代做法 |
|---|---|---|
| 正常生成 | 检索资料、生成脚本、检查当前版本，经三阶段审核后完成 | 只有一段普通聊天输出 |
| 缺关键信息 | 说明缺口，等待补充后继续 | 自动假定受众或目标时长 |
| 无素材 | 基于空结果决定改写查询、追问或停止 | 用另一个产品的资料拼出答案 |
| 工具失败 | 返回真实失败，模型观察后调整，保留已有成果 | 把失败记录为成功或伪造返回值 |
| 超时后修正或明确失败 | 压缩后重新估时，或清楚说明无法满足 | 修改语速、目标值或手填总时长来通过 |
| 事实可追溯 | 原文实质支持断言，功能、数字和适用条件一致 | 仅检查引用 ID 存在 |
| 动态决策 | 至少两条真实模型路径根据不同工具结果改变后续动作 | 固定分支、自动重试或预设决策日志 |
| 人工介入 | 三阶段可暂停，使用同一任务 ID 和当前审核 ID 跨进程恢复，意见进入后续模型上下文；同任务恢复互斥 | 仅打印“待审核”后自动通过，或重复消费旧审核 |
| 有界执行 | 模型和工具调用达到上限时明确未完成，计数跨恢复保留 | 无限尝试或恢复时清零 |
| 技能覆盖 | 技能加载与实际产物、动作关联，真实与 Mock 分开报告 | 只统计有多少 SKILL.md 文件 |

## 交付与边界

按照考核要求提交代码、可执行测试、合成数据、输入及实际输出、Trace、五份说明和环境配置示例。至少三组运行材料应覆盖正常、信息或资料不足、工具失败，并覆盖其余验收点。目前仓库保留这些输入及真实运行结果，但存在记录不等于场景通过；工程测试通过也不能补足真实模型未完成的业务验收。实际运行结果、未通过项和证据位置统一在 [评估文档](03-evaluation.md) 中记录。

本项目是单机考核作品。SQLite checkpoint 与操作系统锁支持正常人审暂停后的跨进程恢复，并防止同一任务被本地进程同时恢复；第一版不承担多用户权限管理、分布式协同审核、任意节点崩溃后的自动续跑、公开网页部署或真实发布职责。Python 工具执行、模型选择动作和人工批准具有不同职责，不以人工批准替代事实依据，也不以工具可运行代替模型能力验证。
