# 叙事结构设计

## 用途与触发

当需要组织完整短视频的开场、展开和收尾，或内容零散缺少主线时使用。负责叙事大纲而不是逐镜头画面。

## 输入

已确认或待审方向、可用事实、目标时长、受众。

## 产出

三至五个叙事节点的 outline，各节点说明信息目的。

## 操作约束

1. 根据任务选择问题—演示—总结、场景—功能—行动等结构，避免每次固定套同一模板。
2. 每个节点只承担一个主要目的，确定先后依赖。
3. 资料只有两条功能时可以围绕操作过程组织，不能用未经证实的数据填充故事。
4. 收尾行动应与用户目标一致；没有购买链接或价格资料时不编造优惠、下载量或限时活动。

## 验证示例

“自动字幕”和“手动修改”两条资料可形成“手动输入困扰—自动生成—检查修改”的大纲，不应新增准确率或节约时间数字。

## 使用证据

运行记录应关联本技能的加载事件、选用理由和实际产生的方向或脚本变化。仅加载本文件不等于完成该能力。
